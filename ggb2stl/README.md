# ggb2stl — GeoGebra → 3D модель для печати

Локальное веб-приложение: сверху слева — встроенный апплет GeoGebra (полноценный, с меню, вводом команд и кнопкой разворота на весь экран), сверху справа — 3D‑превью готовой модели, внизу — параметры, кнопки «Построить» / «Скачать STL», и в самом низу страницы — отчёт (сколько точек/отрезков получилось + предупреждения). Конструкция в апплете автоматически сохраняется в браузере и восстанавливается при обновлении страницы.

## Что оно делает

По нажатию «Построить модель» приложение читает текущую конструкцию из апплета (через официальный JS API GeoGebra + XML конструкции) и строит 3D‑модель:

- каждая видимая **точка** → **полусфера** (купол вверх, плоское основание);
- **отрезок / вектор**, стороны **многоугольника**, звенья **ломаной (PolyLine)** → **полуцилиндр** (валик со скруглённым верхом);
- **любая прямая** — построенная как `Line(A,B)`, серединный перпендикуляр (`LineBisector`), биссектриса угла (`AngleBisector`), перпендикулярная/параллельная прямая, касательная, полярная прямая и т.д. — тоже превращается в полуцилиндр, обрезанный по границе области модели (плюс отступ), так как бесконечную прямую напечатать нельзя. Это работает для любого инструмента, создающего прямую, а не только для перечисленных — подробнее см. ниже;
- **луч (Ray)**, построенный через две точки → аналогично, но обрезается только «дальний» конец;
- **окружность (Circle)** — через две точки, через центр и число-радиус, или через три точки — превращается в кольцо из полуцилиндров-валиков со сглаживающими куполами‑стыками;
- **дуга (CircleArc, CircumcircleArc, Semicircle)** и **сектор (CircleSector, CircumcircleSector)** — превращаются в такую же дугу-валик; у сектора дополнительно печатаются два радиуса от центра;
- **эллипс (Ellipse)** через два фокуса и число/точку/отрезок — превращается в замкнутое кольцо-валик, как окружность, но вытянутое;
- **метка угла (Angle)** — `Angle(A,B,C)` (по трём точкам) и `Angle(Многоугольник)` (сразу для всех вершин) — превращается в маленькую дугу-метку у вершины угла. У этих дуг **отдельные радиус и толщина** (обычно намного меньше, чем у обычных отрезков/окружностей, чтобы метка угла не выглядела как полноценная деталь конструкции); радиус автоматически уменьшается, если рядом короткая сторона, чтобы метка не «вылезала» за неё.

Если у объекта в самом GeoGebra включён **пунктирный/точечный стиль линии** (через панель стилей или «Настройки объекта → Стиль»), это тоже переносится в модель: вместо одного сплошного валика печатается **чередование коротких валиков и промежутков** (для пунктира) или **ряд отдельных полусфер-точек** (для точечной линии) — так же, как это выглядит на экране в GeoGebra. Поддерживаются все 4 варианта GeoGebra: пунктир короткий, пунктир длинный, точечная линия, штрихпунктирная линия — для отрезков, векторов, сторон многоугольника, звеньев ломаной, любых прямых и лучей, окружностей, эллипсов, дуг/секторов и меток углов. Сплошные (по умолчанию) объекты печатаются как раньше, без изменений.

Показывается **3D‑превью** модели прямо на странице (вращение — перетаскивание мышью, зум — колесо), и только после этого можно скачать **STL**.

**Подложка опциональна** (чекбокс «Добавить подложку», по умолчанию включена): с подложкой все фигуры «утоплены» на пару десятых миллиметра в общую прямоугольную плашку — печатается одним цельным объектом. Без подложки купола/валики стоят прямо на столе принтера — каждый из них уже сам по себе цельное, «водонепроницаемое» тело, так что печатается корректно и без плашки.

Всё это работает как рельеф 2D‑чертежа: у полусфер и полуцилиндров ровно одна плоская сторона (низ), поэтому режим по умолчанию рассчитан на плоские (2D) конструкции — Graphing/Geometry/Classic без 3D‑вида. Координата z при этом игнорируется.

Есть и второй режим — **«Полный 3D»**: точки → обычные сферы, отрезки → обычные цилиндры, координаты (x,y,z) берутся как есть, без подложки (окружности/дуги/эллипсы в этом режиме пока не поддерживаются — см. ограничения). Подходит для конструкций из 3D Graphics.

Модель экспортируется в бинарный **STL**, который можно сразу открывать в слайсере (Cura, PrusaSlicer, Bambu Studio и т.п.). Boolean-объединение фигур не выполняется — все они просто накладываются друг на друга; современные слайсеры корректно режут такие перекрывающиеся, но замкнутые ("watertight") тела в один сплошной объект.

## Расположение на странице

- **Сверху слева** — апплет GeoGebra. Кнопка «⛶ На весь экран» в правом верхнем углу апплета разворачивает его на весь экран браузера (стандартный Fullscreen API) — удобно строить конструкцию, апплет сам подгоняет размер (`ggbApplet.setSize`) под доступное место и обратно при сворачивании.
- **Сверху справа** — 3D‑превью последней построенной модели.
- **Снизу** — параметры модели и кнопки «Построить модель и показать превью» / «Скачать STL».
- **В самом низу страницы** — отчёт: сколько точек, отрезков/дуг и треугольников получилось, плюс предупреждения о том, что не удалось превратить в 3D.

## Как запустить

Файлы полностью статические — сборка не требуется.

1. Откройте `index.html` двойным кликом в браузере (Chrome/Edge/Firefox).
   - Если браузер блокирует что-то при открытии как `file://`, поднимите локальный сервер из папки, например `python3 -m http.server`, и откройте `http://localhost:8000`.
2. Дождитесь загрузки апплета GeoGebra (сверху слева). При необходимости разверните его на весь экран кнопкой «⛶» для удобства построения.
3. Загрузите свой файл `.ggb` одним из двух способов:
   - кнопка «Выберите файл» в блоке параметров внизу (загружает файл прямо в апплет);
   - либо меню апплета «Файл → Открыть».
4. При желании подвигайте/отредактируйте точки, отрезки, окружности и т.д. прямо в апплете — экспортируется текущее состояние конструкции.
5. Настройте параметры внизу (см. ниже) и нажмите **«Построить модель и показать превью»** — справа сверху появится вращаемое 3D‑превью.
6. Если всё устраивает — нажмите **«Скачать STL»**. Файл `model.stl` скачается в папку загрузок браузера. Если после этого меняете параметры или конструкцию — нажмите «Построить» ещё раз перед повторным скачиванием (STL всегда соответствует последней построенной модели, а не текущим значениям полей).
7. Отчёт о том, что получилось (число точек/отрезков/треугольников и предупреждения) — в самом низу страницы, под блоком параметров.

Конструкцию в апплете можно спокойно оставлять недостроенной и обновлять страницу — она сохраняется в браузере (localStorage) и подхватывается автоматически заново. Чтобы начать с чистого листа — ссылка «забыть сохранённое» рядом с кнопкой загрузки файла.

## Параметры

- **мм на 1 единицу GeoGebra** — во сколько миллиметров превращается одна единица координатной сетки (масштаб чертежа).
- **Радиус точки (мм)** — радиус купола-полусферы в готовой модели.
- **Радиус отрезка (мм)** — радиус (высота) полуцилиндра-валика; используется и для «трубки» окружностей/дуг/эллипсов.
- **Радиус дуги угла (мм)** и **Толщина дуги угла (мм)** — отдельные, независимые от «Радиуса отрезка» настройки специально для меток углов (Angle). По умолчанию меньше, чем у отрезков, чтобы метка угла выглядела как метка, а не как ещё одна деталь конструкции. Это базовый (общий) радиус: если в самом апплете GeoGebra у конкретного угла изменён параметр «Размер» (в свойствах объекта или на панели стилей), итоговый радиус этой конкретной метки масштабируется пропорционально — вдвое больший «Размер» в GeoGebra даёт вдвое больший радиус дуги в модели, вдвое меньший — вдвое меньший, относительно значения по умолчанию в GeoGebra (30). Как и раньше, радиус всё равно не может превысить 90% от короткой смежной стороны.
- **Добавить подложку** — включает/выключает общую плашку-основание (только режим «Рельеф»).
- **Толщина подложки (мм)** и **Отступ от краёв (мм)** — размеры плашки, если она включена.
- **Заглубление фигур в подложку (мм)** — на сколько мм купола/валики «утапливаются» в подложку, чтобы не было тонкого шва на стыке (действует только если подложка включена).
- **Точность сетки** — количество сегментов при построении окружностей/дуг; больше — более гладкая поверхность, но больше треугольников в STL.

Разумные значения по умолчанию уже выставлены (10 мм/единица, точки Ø3 мм, отрезки Ø2 мм, подложка 2 мм) — обычно можно сразу нажимать кнопку.

## Что поддерживается

- Точки (Point) — видимые.
- Отрезки (Segment) и векторы (Vector) между двумя точками.
- Многоугольники (Polygon) — каждая сторона превращается в полуцилиндр.
- Ломаные (PolyLine) — каждое звено превращается в полуцилиндр.
- Окружности (Circle) — варианты «через две точки», «центр + число-радиус» и «через три точки».
- Полуокружности (Semicircle), дуги (CircleArc, CircumcircleArc) и сектора (CircleSector, CircumcircleSector — с двумя радиусами).
- Эллипсы (Ellipse) через два фокуса и число/точку/отрезок, задающие длину большой полуоси.
- Прямые (Line) — **любые**, независимо от инструмента: обычная прямая через две точки, серединный перпендикуляр, биссектриса угла, перпендикулярная/параллельная прямая, касательная к окружности, полярная прямая и т.д. Определяются не по имени команды, а по типу объекта ("line") через коэффициенты уравнения `a·x+b·y+c=0`, которые GeoGebra хранит для любой прямой — тот же приём, которым GeoGebra сама поддерживает `x(l)`, `y(l)`, `z(l)` для прямой `l`. Рисуются как отрезок, обрезанный по границе области модели (плюс отступ), так как бесконечную прямую напечатать нельзя.
- Лучи (Ray), построенные через две точки — аналогично, но обрезается только дальний (бесконечный) конец, начало остаётся на месте.
- Метки углов (Angle) — `Angle(A,B,C)` (по трём точкам) и `Angle(Многоугольник)` (по всем вершинам сразу); печатаются со своим отдельным радиусом/толщиной, который дополнительно масштабируется параметром «Размер» этого конкретного угла в GeoGebra (если он менялся) — так разные по «Размеру» углы в одной конструкции получаются разными и в модели.
- Стиль линии (сплошная/пунктирная/точечная/штрихпунктирная), выставленный в самом GeoGebra для конкретного объекта, — переносится в модель как чередование коротких валиков и промежутков (или ряд отдельных точек-полусфер для точечной линии). Работает для отрезков/векторов/сторон многоугольника/звеньев ломаной, любых прямых и лучей, окружностей, эллипсов, дуг/секторов и меток углов.
- Видимость объектов учитывается: скрытые объекты не попадают в модель (даже если их опорные точки видимы).
- Любой другой видимый объект, который приложение не умеет превращать в 3D (графики функций, локусы, общие коники и т.п.), явно перечисляется в предупреждениях после построения модели (с именем и типом), чтобы было понятно, что именно не попало в STL.

## Ограничения (v1)

- **Графики функций/кривые, локусы, произвольные коники (гиперболы, параболы)** — пока не превращаются в 3D. Приложение сообщит о них в предупреждениях по имени и типу; если что-то из этого нужно — напишите, что именно, это можно добавить прицельно.
- **Метки углов** поддержаны только для `Angle(A,B,C)` и `Angle(Многоугольник)`. Вариант `Angle(вектор, вектор)` / `Angle(прямая, прямая)` (без явных точек-вершин) пока не распознаётся — придёт предупреждение с именем объекта. Направление дуги (по/против часовой) соответствует умолчанию GeoGebra (против часовой от первой точки ко второй), но особые случаи с «рефлексным» углом (>180°, настройки `allowReflexAngle`/`forceReflexAngle`) не учитываются — метка может не совпасть по направлению с тем, что показано в самом апплете, если там включена эта настройка.
- **Лучи (Ray)** поддержаны только для варианта «через две точки» (`Ray(A,B)`) — в отличие от прямых, для которых поддержаны вообще все инструменты (см. выше).
- **Окружности/дуги/сектора/эллипсы** в режиме «Полный 3D» не поддерживаются (ориентация плоскости неоднозначна без чтения нормали конструкции) — используйте режим «Рельеф».
- **Пунктирный/точечный стиль** учитывается только в режиме «Рельеф»; в режиме «Полный 3D» такие объекты всё равно печатаются, но сплошными (без разрывов) — это чисто визуальная настройка для плоского рельефа, где разрывы физически осмысленны, в «полном 3D» её не переносим. Длина штрихов/точек привязана к «Радиусу отрезка» (или «Толщине дуги угла» для меток углов) и не настраивается отдельно.
- В режиме «Рельеф» координата z точек не используется (чертёж считается плоским). Для настоящих 3D‑построений используйте режим «Полный 3D».
- Идентификация связей «какая точка с какой соединена» берётся из внутреннего XML конструкции GeoGebra (`getXML()`), а не из парсинга текста команд — это надёжно работает для поддерживаемых команд, но не покрывает более экзотические инструменты.
- Экспорт делает не булево объединение, а перекрывающиеся замкнутые тела. Это стандартно нормально печатается почти во всех слайсерах, но если ваш слайсер жалуется на self-intersections — прогоните STL через авто-восстановление сетки (в большинстве слайсеров такая опция есть, например «Fix mesh» / netfabb basic).
- 3D‑превью использует Three.js, загружаемый с CDN (cdnjs) — для него нужен интернет; сам экспорт в STL от интернета не зависит (кроме самого апплета GeoGebra, который тоже грузится с geogebra.org).
- Полноэкранный режим апплета использует стандартный браузерный Fullscreen API — в редких/старых браузерах без его поддержки кнопка покажет предупреждение вместо разворота, но остальной функционал не затрагивается.
- Автосохранение конструкции использует `localStorage`, который привязан к origin страницы. При открытии `index.html` напрямую как `file://` некоторые браузеры (это подтверждено и в тестах на headless-движке) блокируют `localStorage` для файловых страниц — тогда автосохранение просто молча не работает (остальной функционал не затрагивается, ошибок в интерфейсе не будет). Если автосохранение важно — запускайте страницу через локальный сервер (`python3 -m http.server` и открыть `http://localhost:8000`), там `localStorage` работает надёжно.

## Структура файлов

- `index.html` — разметка страницы (апплет + превью сверху, параметры снизу).
- `app.js` — интеграция с GeoGebra JS API, извлечение геометрии (включая дуги/сектора/эллипсы), сборка сцены, полноэкранный режим, 3D‑превью, экспорт.
- `meshgen.js` — чистые JS-генераторы треугольных сеток (полусфера, полуцилиндр, коробка-подложка, сфера/цилиндр для режима «Полный 3D»).
- `stlexport.js` — сериализация треугольников в бинарный STL.
- `style.css` — оформление.

Файлы `test_*.js` в этой же папке — юнит- и интеграционные тесты (запускаются через `node test_meshgen.js` и т.д.; `test_dom_smoke.js` и `test_dom_smoke_storage.js` грузят саму `index.html` в jsdom и кликают по кнопкам — включая полный цикл автосохранения/восстановления конструкции, — чтобы ловить ошибки вёрстки/обработчиков), в саму веб-страницу не подключены и для работы приложения не нужны.
